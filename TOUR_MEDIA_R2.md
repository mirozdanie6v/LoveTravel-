# MAX TOUR — ТЗ на хранение фото экскурсий в Cloudflare R2

## Цель

Исключить внешние hotlink-зависимости для фотографий каталога MAX TOUR. Все изображения экскурсий должны храниться в Cloudflare R2 и отдаваться клиенту с основного домена `max-tour-demo.viiversion.com`.

## Архитектура

- R2 bucket: `max-tour-demo-v28-media`
- Worker binding: `TOUR_MEDIA`
- Публичный R2-домен не используется.
- Клиентские URL: `/tour-media/<tour-id>/<file>`.
- Worker перехватывает `/tour-media/*`, читает соответствующий объект из R2 и возвращает его с корректным `Content-Type` и долгим immutable-cache.
- Каталог и интерфейс не должны содержать прямых URL Tilda, Unsplash, Pelago, Booking, Vinpearl и других внешних CDN.

## Каталог

- 15 экскурсий.
- Для каждой экскурсии минимум 3 уникальных изображения.
- `image` — обложка экскурсии.
- `fallbackImage` — та же локальная обложка.
- `gallery` — минимум 3 локальных пути той же экскурсии.
- Путь каждой картинки обязан начинаться с `/tour-media/<tour-id>/`.

## Источники и происхождение

`src/tour-media-sources.json` — единственный реестр исходных URL и соответствующих им R2-ключей. Исходные URL используются только при подготовке/засеве R2 и не попадают в runtime-каталог.

## Контроль качества

Перед сборкой `scripts/validate-tour-media.mjs` обязан проверить:

1. присутствуют ровно все 15 tour id;
2. у каждой экскурсии минимум 3 изображения;
3. runtime-пути не содержат `http://` или `https://`;
4. каждый путь относится к папке своей экскурсии;
5. каждому runtime-пути соответствует объект в source manifest;
6. в manifest нет дубликатов и неиспользуемых объектов.

`scripts/prepare-tour-media.mjs` скачивает исходники во временную `.tour-media/`, проверяет HTTP-ответ, минимальный размер и сигнатуру реального изображения до загрузки в R2.

После деплоя `scripts/verify-live-tour-media.mjs` проверяет production-каталог и делает HEAD-запрос каждого уникального `/tour-media/*`: HTTP 200, `image/*`, ненулевой размер.

## Последовательность деплоя

1. Tests + media policy validation + build.
2. Найти или создать R2 bucket `max-tour-demo-v28-media`.
3. Скачать и проверить исходные файлы во временную `.tour-media/`.
4. Загрузить все объекты в R2 с `Cache-Control: public, max-age=31536000, immutable`.
5. Подставить production D1 ID и сохранить R2 binding в Cloudflare config.
6. Применить D1 migrations.
7. Задеплоить Worker `max-tour-demo-v28`.
8. Привязать только `max-tour-demo.viiversion.com`.
9. Выполнить live-проверку приложения, каталога и всех R2-фотографий.

## Критерии приёмки

Деплой считается успешным только если одновременно выполняются условия:

- основной production — `max-tour-demo.viiversion.com`;
- каталог содержит 15 экскурсий;
- у каждой минимум 3 изображения;
- ни `image`, ни `fallbackImage`, ни `gallery` не содержат внешних URL;
- все перечисленные изображения доступны через `/tour-media/*` с HTTP 200;
- все изображения реально обслуживаются R2 binding `TOUR_MEDIA`;
- сборка и live verification завершаются без ошибок.

## Откат

Откат приложения выполняется возвратом предыдущей версии Worker/каталога. Загруженные R2-объекты не удаляются автоматически: они являются независимым immutable-набором и не мешают откату к предыдущей версии.
