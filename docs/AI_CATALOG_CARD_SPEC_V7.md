# MAX TOUR — AI recommendation card = catalog card (v7)

## Цель

Карточка экскурсии, которую показывает AI-консультант, не является отдельным UI-компонентом. Для экскурсии, существующей в каталоге, AI должен показывать тот же каталоговый `tour-card`, с тем же DOM, изображением, ценой, бейджами, избранным и обработчиками открытия экскурсии.

AI выбирает только `tourId`. Отрисовку карточки выполняет интерфейс каталога.

## Обязательные правила

1. **Один визуальный компонент**
   - AI не генерирует собственную упрощённую карточку для существующей экскурсии.
   - Используется существующая `.tour-card` из каталога: предпочтительно через оригинальный renderer, иначе через точное клонирование уже отрисованной каталоговой карточки.
   - Карточка не получает AI-специфичную сетку, типографику или отдельные CTA внутри самой карточки.

2. **Одинаковое поведение**
   - Нажатие на карточку вызывает тот же `openTour(tourId)`, что и в каталоге.
   - Кнопка избранного использует тот же `toggleLike(...)` и не должна открывать экскурсию.
   - Экран экскурсии и дальнейший booking flow полностью общие с каталогом.

3. **Контекст AI не теряется**
   - Перед открытием экскурсии из AI сохраняются известные параметры: `tourId`, дата, взрослые, дети, малыши, формат.
   - При переходе к бронированию существующий prefill-механизм использует этот booking intent.
   - Уже известные пользователю/AI параметры не запрашиваются повторно без необходимости.

4. **География и availability остаются выше UI**
   - AI может передать в UI только экскурсии, разрешённые текущей route-policy.
   - Скрытие неподходящей карточки продолжает работать по `data-tour-id`.
   - Карточка не является источником availability; источник истины — каталог/Booking Core.

5. **Маршрут по запросу — отдельный тип**
   - Если готовой экскурсии в каталоге нет (например, допустимый маршрут по запросу), нельзя имитировать каталоговую карточку и придумывать цену.
   - Для такого случая остаётся отдельный блок «Маршрут по запросу» с явной пометкой, что цена и наличие подтверждаются после уточнения.

## UX в AI

Последовательность:

`сообщение пользователя → короткий ответ AI → 1–3 настоящие карточки каталога → открытие экскурсии → общий booking flow`.

Карточка внутри AI должна визуально совпадать с карточкой той же экскурсии в каталоге: фото, пропорции, шрифты, бейджи, цена, отступы и интерактивные элементы.

## Техническая реализация v7

- Новый слой `src/ai-catalog-card-v7.js` выполняется после `ai-consultant-v5.js` и `ai-location-guard-v6.js`.
- Он заменяет только старые AI-карточки вида `.ai-recommendation.ai-sales-card[data-tour-id]`.
- Сначала ищется уже существующая настоящая `.tour-card` с тем же `tourId` вне AI-экрана и делается точный clone.
- Если такой DOM ещё не создан, слой пытается использовать оригинальный чистый renderer карточки из глобального кода прототипа. Кандидаты принимаются только если возвращают `.tour-card` и не выполняют screen/navigation mutations.
- Полученная карточка сохраняет исходный `onclick`, `toggleLike`, изображения и каталоговые классы; добавляются только служебные `data-tour-id`, `data-ai-catalog-source="catalog"` и класс `ai-catalog-card-v7`.
- Старые AI-стили применяются только к `.ai-recommendation.ai-sales-card`, поэтому не меняют настоящий `.tour-card`.
- MutationObserver v7 идемпотентен: уже заменённые карточки не перерисовываются повторно.

## Acceptance criteria

- [ ] Одна и та же экскурсия в каталоге и AI имеет один и тот же `tour-card` markup/class family.
- [ ] В AI нет старых кнопок «Подробнее / Забронировать» внутри существующей экскурсионной карточки; работает каталоговый сценарий целиком.
- [ ] Клик по AI-карточке открывает тот же экран экскурсии, что клик из каталога.
- [ ] Like/favorite ведёт себя так же, как в каталоге.
- [ ] Выбранные в AI дата и состав группы сохраняются перед открытием экскурсии и подставляются в booking flow.
- [ ] Ханой не получает карточки Далата; Нячанг → Далат остаётся разрешённым.
- [ ] Для отсутствующего в каталоге, но допустимого направления показывается «Маршрут по запросу», а не поддельная карточка.
- [ ] Нет циклической DOM-перерисовки и зависания Mini App.
- [ ] `npm test` и `npm run build` проходят.
- [ ] После deploy live-проверка `max-tour-demo.viiversion.com` подтверждает визуальный parity и общий booking flow.
